[Gemini API Managed Agents](TODO) run the agent loop and the model on Google's side. With [Bring Your Own Sandbox](TODO), the agent's shell and file tools execute in a sandbox you control instead. Connect a Sprite as that sandbox and the agent's commands, filesystem, and network egress stay on a Firecracker microVM in your Fly.io organization.

## How it works

You create a self-hosted environment in the Gemini API. A Sprite runs the `gemini-api` CLI's connector, which links the Sprite to that environment using an environment key. When you send the agent an interaction that targets the environment, its tool calls run inside the Sprite and the results go back to Gemini.

The connector authenticates with the **environment key** only. Your Gemini API key stays on your own machine and never reaches the Sprite.

## Before you begin

You need:

- A **Gemini API key** with access to Managed Agents, exported as `GEMINI_API_KEY`.
- The **`gemini-api` CLI** on your local machine, to send interactions. {/* TODO: local install command */}
- The **`sprite` CLI**, installed and logged in:

```bash
curl -fsSL https://sprites.dev/install.sh | sh
sprite login
```

## Create a self-hosted environment

```bash
curl -fsSL -X POST \
  "https://generativelanguage.googleapis.com/v1beta/environments" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"mode": "self_hosted"}'
```

Export the environment ID and key from the response:

```bash
export GEMINI_ENVIRONMENT_ID="environments/..."
export GEMINI_ENVIRONMENT_KEY="ek_..."
```

<Warning>
The environment key is returned only once, when the environment is created. Store it somewhere safe.
</Warning>

## Connect a Sprite

### Create the Sprite and install the CLI

```bash
sprite create --skip-console gemini-byos

sprite exec -s gemini-byos --no-stdin -- bash -c \
  "curl -fsSL https://raw.githubusercontent.com/google-gemini/gemini-api-cli/main/scripts/install.sh | bash"
```

### Store the environment key

Write the key to a file only your user can read. The connector service reads it from there, so the key never appears in a command line or process listing.

```bash
sprite exec -s gemini-byos --no-stdin --env "GEMINI_ENVIRONMENT_KEY=$GEMINI_ENVIRONMENT_KEY" -- bash -c \
  'umask 077; printf "GEMINI_ENVIRONMENT_KEY=%s\n" "$GEMINI_ENVIRONMENT_KEY" > ~/.gemini-env'
```

### Run the connector as a service

You can run `gemini-api environments connect` directly with `sprite exec`, but it stops when that command ends, and the Sprite [pauses](/concepts/lifecycle) when it goes idle. A connector only makes outbound connections, so the Sprite has no inbound traffic to keep it awake. Run the connector as a Sprite [service](/concepts/services) instead, so it restarts if it crashes, and have it hold a [Task](/keeping-sprites-running) so the Sprite stays active while it is connected.

Write the start script:

```bash
sprite exec -s gemini-byos --no-stdin -- bash -c 'cat > ~/gemini-connect.sh <<"EOF"
#!/usr/bin/env bash
set -a; . "$HOME/.gemini-env"; set +a
export PATH="$HOME/.local/bin:$PATH"

# Hold the Sprite active: a 5-minute task, refreshed every minute.
( while true; do
    sprite-env curl -X PUT /v1/tasks/gemini-connect -d "{\"expire\": \"5m\"}" >/dev/null 2>&1
    sleep 60
  done ) &
heartbeat=$!
trap "kill $heartbeat 2>/dev/null; sprite-env curl -X DELETE /v1/tasks/gemini-connect >/dev/null 2>&1" EXIT

gemini-api environments connect
EOF
chmod +x ~/gemini-connect.sh'
```

Then create the service:

```bash
sprite exec -s gemini-byos --no-stdin -- \
  sprite-env services create gemini-connect --cmd /home/sprite/gemini-connect.sh
```

The connector's output goes to `/.sprite/logs/services/gemini-connect.log`.

<Info>
While the connector runs, the task keeps the Sprite active, and an active Sprite is billed for compute. To stop billing between uses, stop the service with `sprite-env services stop gemini-connect` and start it again when you need it. If the connector crashes without cleaning up, the task expires within five minutes and the Sprite can pause.
</Info>

## Run an interaction

From your local machine, send the agent an interaction that targets your environment:

```bash
gemini-api agent run \
  "Create hello.txt and run uname -a in bash." \
  --agent antigravity-preview-05-2026 \
  --body "{\"environment\": \"$GEMINI_ENVIRONMENT_ID\"}"
```

The agent's commands run on the Sprite, and `hello.txt` stays on its disk.

## Use a Fly Machine instead

To use a plain [Fly Machine](https://fly.io/docs/machines/) instead of a Sprite, store the key as an app secret rather than passing it with `-e`. That keeps it out of the Machine's config:

```bash
export FLY_APP="your-fly-app"
fly apps create "$FLY_APP" || true
fly secrets set -a "$FLY_APP" --stage GEMINI_ENVIRONMENT_KEY="$GEMINI_ENVIRONMENT_KEY"

fly machine run ubuntu:24.04 -a "$FLY_APP" -- bash -c \
  "apt-get update && apt-get install -y curl ca-certificates && \
   curl -fsSL https://raw.githubusercontent.com/google-gemini/gemini-api-cli/main/scripts/install.sh | bash && \
   PATH=\"\$HOME/.local/bin:\$PATH\" gemini-api environments connect"
```

## Clean up

Deleting a Sprite deletes its disk and checkpoints, so copy out anything the agent wrote that you want to keep first.

```bash
sprite destroy -s gemini-byos --force

# Or, for a Fly Machine:
fly apps destroy "$FLY_APP" --yes
```

## Troubleshooting

| Symptom | Likely cause | Check / fix |
|---|---|---|
| Interactions hang, then time out | The connector isn't running, or the Sprite paused | `sprite exec -s gemini-byos -- sprite-env services list` should show `gemini-connect` running. `sprite-env curl -s /v1/tasks` should show the `gemini-connect` task with a future `expires_at`. |
| The connector exits right after it starts | The environment key is wrong, or `~/.gemini-env` is missing | Read `/.sprite/logs/services/gemini-connect.log`. |
| `gemini-api: command not found` in the log | The CLI install failed, or it installed somewhere other than `~/.local/bin` | Rerun the install step and check its output. |
